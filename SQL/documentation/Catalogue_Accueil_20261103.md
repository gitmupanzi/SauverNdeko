# Catalogue : accueil et compatibilité des licences

La migration `20261103_08_catalogue_accueil.sql` retire Catalogue du lanceur (`AfficherDansEspace=false`) et le classe en `FONCTIONNALITE`, non commercialisable et sans parent de présentation. Le catalogue devient l’accueil `/catalogue` ; l’espace de travail conserve ses propres modules autorisés. Pour l’administrateur global, le lanceur contient désormais huit modules métier et quatre fonctionnalités associées, dont Référentiels protégé par ses droits ERP existants.

Le code historique `catalogue` reste dans `T_ModuleApplication` et les réponses de catalogue des licences. La migration ne change aucun `EstSocle`, `CodeIncluant`, `Actif`, rôle, utilisateur ou abonnement. Les activations historiques de Catalogue continuent à inclure Produits, Structures, Professionnels et Santé. Reclasser la présentation ne révoque donc pas les accès déjà acquis et ne crée aucun accès nouveau. L’interface de découverte ne doit plus proposer Catalogue comme module à acheter ; la gestion des licences conserve la compatibilité avec son code historique.

Le seul enfant de présentation attendu, Santé, perd son `ModuleParentCode='catalogue'` avant le reclassement. Son `CodeIncluant='catalogue'`, ses données, son activité et ses API sont conservés ; sa tuile reste masquée comme après la migration 07. Tout autre enfant inattendu provoque un refus transactionnel de la migration : aucun rattachement client supplémentaire n’est supprimé silencieusement.

Cette évolution ne crée ni colonne, vue, contrainte ni fonction. Les définitions canoniques 06+07 restent exactes ; le seed fermé du catalogue applicatif réutilise les métadonnées courantes lors de la préparation d’une installation. Les chemins frontend sont pris en charge séparément et ne modifient pas les licences serveur.

Vérifications exécutées sur `sauverndeko_test_cataloguehome08_470c904e` : migration appliquée puis rejouée, contrôle exact des seules métadonnées prévues, empreintes des 78 tables historiques conservées hors ces métadonnées, treize codes inchangés, vues et triggers identiques. Neuf tests API et sept tests SQL ont réussi, dont la conservation des licences et de l’inclusion Catalogue, le refus de Produits sans licence, les gardes Référentiels, le masquage du lanceur et le refus d’un enfant de présentation inattendu.
